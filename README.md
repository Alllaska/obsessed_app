# Handoff: Daily Tracker (распорядок дня)

## Overview
Оффлайн мобильное приложение для отслеживания распорядка дня. Главный (и пока единственный) экран — вертикальная временная шкала: слева время, по центру цветная круглая иконка на соединительной линии, справа карточка задачи. Задачи автоматически сортируются по времени, помечаются выполненными, редактируются и добавляются. Всё хранится локально (без сети). Приложение персональное — настройки и дефолтные задачи под конкретного пользователя.

## About the Design Files
Файл `Daily Tracker.html` в этом пакете — **дизайн-референс, созданный на HTML/CSS/JS**. Это рабочий прототип, демонстрирующий внешний вид и поведение, **а не продакшн-код для прямого копирования**. Задача — **воссоздать этот дизайн в целевой среде Android** (нативно на Kotlin/Jetpack Compose, либо Flutter/React Native — на выбор разработчика, если проекта ещё нет), используя идиоматичные для платформы паттерны: списки/ленивые колонки, локальное хранилище (DataStore/Room/SharedPreferences), bottom sheet'ы, диалоги.

Прототип полностью функционален — открой его в браузере, чтобы пощупать все взаимодействия. Логика (модель данных, сортировка, хранение, правила автоскролла) описана ниже и читается прямо в `<script>` внутри файла.

## Fidelity
**High-fidelity (hifi).** Финальные цвета, типографика, отступы, скругления и взаимодействия. Воссоздавать UI попиксельно, но средствами платформы (нативные компоненты вместо HTML-разметки).

## Interactions & Behavior

- **Тап по времени** строки → открыть шторку в режиме редактирования этой задачи.
- **Тап по иконке ИЛИ по заголовку** задачи → переключить «выполнено».
  - Выполнено: иконка обесцвечивается (`filter: grayscale(1) brightness(0.55)`, тень убирается), карточка `opacity: 0.55`, заголовок зачёркнут (`line-through`) и серый `#8a8a90`, строки описания/значения тоже зачёркнуты. Повторный тап снимает отметку.
- **Тап по «+»** (вся строка кликабельна) → шторка в режиме создания.
- **Тап по невидимому углу** → диалог «Обновить?».

### Автосортировка по времени
Все задачи всегда отсортированы по времени по возрастанию (раньше — выше, позже — ниже). Сортировка стабильная: при равном времени сохраняется исходный порядок. Задачи без валидного времени уходят в самый низ. При изменении времени в шторке задача мгновенно переезжает на нужное место. Сама линия шкалы не имеет временных меток — это просто непрерывная линия; порядок задаётся сортировкой.

### Автоскролл при отметке выполненным
Когда задача **становится** выполненной (не при снятии отметки), экран плавно (`smooth`) прокручивается так, чтобы эта задача оказалась вверху (её верх ≈ верх вьюпорта, с отступом ~14px).
**Исключение / условие:** прокрутка происходит **только если все задачи выше неё уже выполнены** (т.е. отмечаешь по порядку сверху вниз). Если выше есть хотя бы одна невыполненная задача (отметил пункт «заранее») — прокрутки нет.

### Анимации/переходы
- Шторка: подложка fade `.2s`; панель slide-up `.26s cubic-bezier(.32,.72,0,1)`.
- Диалог: scale `.2s cubic-bezier(.32,.72,0,1)`.
- Нажатия: время `opacity .5` на active; иконка `scale(0.9)` на active; иконка-вариант `scale(0.9)` на active.

## State Management

Модель данных — слой «дефолт + переопределения», всё в локальном хранилище.

- **DAY** — массив встроенных (дефолтных) задач. Каждый объект:
  `{ id, time:"HH:MM", icon, title, sub?, exercises?: [[name, reps], ...] }`.
  Цвет иконки НЕ хранится в задаче — он берётся из `ICON_META` по ключу иконки.
- **store** — объект переопределений, сериализуется в localStorage под ключом `dailyTracker_state_v1`. Структура:
  - `store[id] = { time?, title?, sub?, desc?, icon?, done?, deleted? }` — пер-задачные оверрайды поверх дефолта. Любое поле, заданное здесь, перекрывает значение из DAY.
  - `store.__custom = [id, ...]` — массив id пользовательских (добавленных) задач. Их базовый объект пустой `{id, custom:true}`, ВСЕ данные живут в `store[id]`.

**Слияние (аксессоры):**
- `getTime(t) = store[id].time ?? t.time`
- `getTitle(t) = store[id].title ?? t.title ?? ""`
- `getSub(t) = store[id].sub ?? t.sub ?? ""`
- `getIcon(t) = store[id].icon ?? t.icon ?? первая иконка`
- `getDesc(t) = store[id].desc ?? (строится из t.exercises, строки вида "name | reps") ?? ""`
- `isDone(t) = !!store[id].done`

**Список к рендеру:** `DAY + custom`, исключая `deleted === true`, затем стабильная сортировка по времени.

**Операции:**
- *Сохранить (редактирование):* записать поля в `store[id]`, сохранить, перерисовать.
- *Создать:* сгенерировать `id = "custom_" + Date.now()`, добавить в `store.__custom`, записать поля в `store[id]`. Пустое название → «Новая задача».
- *Удалить:* для `custom_*` — убрать id из `__custom` и удалить `store[id]`; для встроенной — пометить `store[id].deleted = true` (т.к. из DAY удалить нельзя).
- *Переключить выполнено:* `store[id].done = !done`.
- *Сброс к дефолту («Да» в «Обновить?»):* очистить весь localStorage-ключ, `store = {}`, перерисовать. Возвращает ровно дефолтную версию DAY.

> На Android: DAY — захардкоженный seed; `store` — DataStore/Room/SharedPreferences (JSON). «Сброс» = очистка таблицы оверрайдов.
